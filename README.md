# Proxima Computers

Сайт сервиса сборки ПК для Казахстана: Next.js 15 (App Router) + React 19 + Tailwind CSS 4 + three.js (React Three Fiber).
Цены в тенге (₸), наличие по городам: Алматы, Астана, Шымкент.

- `/` — главная: 3D-модель витринной сборки и переходы в разделы.
- `/builds` — готовые сборки: полный состав, цена, «Настроить» (в конструктор) и «Заказать».
- `/process` — как мы работаем: шаги, что входит в сборку, гарантии, частые вопросы.
- `/order` — заявка. `/order?parts=id,id…&title=…` прикладывает конфигурацию (так сюда ведут конструктор и «Сборки»).
- `/builder` — конструктор: полный каталог, фильтр по городу и наличию, 3D-инспектор каждой детали,
  живая 3D-модель сборки и проверка совместимости в реальном времени. `/builder?preset=orbit` открывает готовую сборку, `?parts=…` — произвольный набор, `?focus=gpu` — нужную категорию.

```bash
npm install
npm run dev      # http://localhost:3000
npm run build && npm start
```

## Архитектура (Clean Architecture)

Зависимости направлены только внутрь: `presentation → application → domain`, `infrastructure → application/domain`.

```
src/
├── domain/                  # Чистая бизнес-логика, без React/Next
│   ├── entities/            # PcComponent, Build, BuildRequest (+ валидация)
│   ├── services/            # Правила совместимости (см. ниже)
│   └── repositories/        # Порты (интерфейсы) хранилищ
├── application/use-cases/   # GetCatalog, GetPresetBuilds, EvaluateBuild/evaluateCandidate, FilterOffers, SubmitBuildRequest
├── infrastructure/          # Адаптеры: in-memory репозитории, каталог, DI-контейнер
├── presentation/
│   ├── components/
│   │   ├── three/           # 3D: models/ (параметрические детали), PcModel, ComponentPreview, visualSpec
│   │   ├── builder/         # Конструктор: AssemblyPanel, Toolbar, CategoryTabs, Inspector, OfferList
│   │   ├── sections/        # Hero, PresetGrid, ProcessSteps, RequestForm, OrderSummary
│   │   ├── layout/ ui/
│   ├── state/               # BuildContext (useReducer) — состояние конфигуратора
│   ├── hooks/ lib/
└── app/                     # Next.js: page (server), layout, api/requests
```

- **Composition root** — `src/infrastructure/container.ts`. Чтобы подключить БД или CRM, реализуйте
  `ComponentRepository` / `BuildRequestRepository` и замените их там — остальной код не меняется.
- Страница — серверный компонент: данные приходят через use cases, на клиент уходит только сериализуемый результат.
- `evaluateBuild` и доменная валидация — чистые функции, одни и те же на клиенте и сервере.

## Админ-панель

`/admin`: вход по паролю, затем три раздела.

- **Обзор**: заявки по статусам с суммами, позиции, которые заканчиваются или закончились.
- **Заявки**: список с фильтром по статусу, контакты, комментарий, приложенная конфигурация и её
  проверка совместимости. Смена статуса только по допустимым переходам
  (новая → в работе / отменена, в работе → выполнена / отменена / новая, закрытые → снова в работу).
- **Каталог**: быстрая правка цены (₸) и остатков по городам прямо в таблице, а также создание,
  полное редактирование и удаление позиций, включая технические параметры для проверки совместимости и 3D
  (сокет, тип памяти, форм-фактор, длина видеокарты, высота кулера / радиатор СЖО, мощность БП, габариты корпуса и т.д.).
  Id новой позиции генерируется из названия. Категорию существующей позиции изменить нельзя.
  Позицию, которая входит в готовую сборку, удалить нельзя: сначала нужно заменить её в сборке.
- **Сборки**: создание, редактирование и удаление готовых сборок для главной и конструктора. Совместимость
  проверяется в форме теми же доменными правилами, что и на сайте. Сохранить можно только полную сборку без ошибок.

Все изменения сразу видны на сайте (`revalidatePath`).

Настройка: скопируйте `.env.example` в `.env.local` и задайте `ADMIN_PASSWORD` и `ADMIN_SESSION_SECRET`
(`openssl rand -base64 48`). Без них вход в админку отключён.

Безопасность:
- сессия хранится в httpOnly-cookie, подписанной HMAC-SHA256, срок 7 дней;
- `/admin/*` закрыт в `middleware.ts`, а каждое серверное действие дополнительно проверяет сессию;
- пароль сравнивается за постоянное время, есть лимит 5 неудачных попыток за 15 минут с одного IP;
- редирект после входа разрешён только на пути `/admin`, страницы помечены `noindex`.

Данные хранятся в JSON-файлах в `data/` (или в `DATA_DIR`): `components.json`, `presets.json` и `requests.json`.
Каталог и сборки заполняются из демо-данных при первом запуске. Запись атомарная и последовательная. Этого достаточно для одного сервера.
Для нескольких инстансов замените `File*Repository` на реализации поверх БД в `container.ts`.

## Стили и темы

Tailwind CSS v4 (CSS-first, без `tailwind.config`). Дизайн-токены — CSS-переменные в `src/app/globals.css`,
подключённые в тему через `@theme inline`: `bg-bg`, `bg-surface`, `text-ink`, `text-muted`, `border-line`,
`text-accent`, `rounded-card`, `rounded-panel`, `shadow-float`, `bg-stage-glow` и т.д.

Светлая и тёмная темы переключаются заменой переменных (`html[data-theme]` или системная настройка), поэтому
отдельные `dark:`-классы не нужны. Переключатель — `src/presentation/theme/ThemeToggle.tsx`, выбор хранится
в `localStorage`, скрипт в `<head>` применяет его до первой отрисовки.

Повторяющиеся элементы вынесены в компоненты `src/presentation/components/ui` (`Button`, `Container`,
`Section`, `Eyebrow`, `Label`, `SectionHeading`), классы склеиваются хелпером `cn`.

## Производительность

Lighthouse (прод-сборка, мобильный профиль): **99–100** с аппаратной графикой; **91–100** в худшем случае
(программный GPU, как на серверах PageSpeed). LCP 0.8 с, CLS 0.

Что для этого сделано:
- **3D запускается лениво.** three.js грузится, а WebGL создаётся только когда сцена рядом с экраном
  (`useNearViewport`) *и* пользователь начал взаимодействовать со страницей (`useUserActivation`: движение мыши,
  касание, скролл, клавиша). До этого — CSS-силуэт корпуса без JS. Место под сцену зарезервировано, поэтому сдвигов нет.
- **Дешёвая сцена:** без карты окружения (PMREM) — полусферный свет; запечённая тень-текстура вместо ContactShadows;
  стекло на `MeshBasicMaterial`; DPR ≤ 1.5; лопасти вентиляторов и рёбра радиатора объединены в одну геометрию;
  материалы в покое пропускают покадровую анимацию.
- **Дешёвый первый кадр:** без `backdrop-filter`, больших `radial-gradient` и бесконечных CSS-анимаций;
  плавная смена темы включается только в момент переключения (`.theme-transition`).

Замер локально:

```bash
NEXT_DIST_DIR=.next-prod npx next build && NEXT_DIST_DIR=.next-prod npx next start -p 3200
npx lighthouse http://localhost:3200 --only-categories=performance --form-factor=mobile
```

## Проверка совместимости

Правила — чистые функции в `src/domain/services/compatibility.ts`; каждое возвращает категории-участники,
поэтому конфликтующие детали подсвечиваются красным и в списке, и в 3D.

| Правило | Уровень |
|---|---|
| Сокет процессора = сокет платы | ошибка |
| Тип памяти (DDR4/DDR5) поддерживается платой | ошибка |
| Форм-фактор платы помещается в корпус | ошибка |
| Длина видеокарты ≤ максимума корпуса | ошибка |
| Высота кулера / размер радиатора СЖО поддерживаются корпусом | ошибка |
| Мощность БП ≥ потребление × 1.3 | ошибка |
| Охлаждение рассеивает TDP процессора | предупреждение |
| Разъём 12V‑2x6 у БП для новых видеокарт | предупреждение |
| PCIe 5.0 SSD на плате без Gen5 M.2 | предупреждение |
| 4 модуля DDR5 | предупреждение |

Для каждого варианта в списке `evaluateCandidate` заранее показывает, что произойдёт, если его выбрать.

## 3D

Модель ПК собрана из параметрических примитивов (без внешних ассетов и HDR). Размеры берутся из характеристик:
длина и толщина видеокарты, число вентиляторов, башенный кулер или СЖО (радиатор 240/280/360 сверху),
2 или 4 планки памяти, форм-фактор платы, цвет корпуса, радиатор у PCIe 5.0 SSD. Невыбранные детали —
полупрозрачные «призраки», конфликтующие — красные. 3D-слой получает только `PcVisualSpec`
(`visualSpec.ts`) и не зависит от цен, сокетов и прочей доменной логики. Клик по детали открывает её
в конфигураторе. Рендер ставится на паузу, когда сцена вне экрана; сцена грузится лениво без SSR.

Цены (₸) и остатки в каталоге — ориентировочные (`src/infrastructure/data/catalog.ts`).
Для реальных данных реализуйте `ComponentRepository` поверх прайса поставщика/1С и подключите в `container.ts`.
